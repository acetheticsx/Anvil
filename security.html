Security

Anvil treats authentication tokens as credentials and keeps GitHub OAuth access tokens on the server.

Last updated: October 8, 2026

Authentication

GitHub App OAuth is handled by server-side endpoints. Session cookies are configured as HttpOnly, Secure in production, and SameSite=Lax. OAuth state is signed and checked before the callback is accepted.

Token handling

GitHub OAuth access tokens are kept server-side. Browser-side personal access tokens are optional and are restricted to GitHub API requests. The app does not intentionally send those tokens to the contributions API or unrelated origins.

Web protections

The deployment sends security headers including HSTS, frame denial, MIME-sniffing protection, a restrictive referrer policy, a permissions policy, and cross-origin opener isolation.

Responsible disclosure

Report security issues through the GitHub security advisory form.

Scope

Security reports should focus on Anvil's application, authentication endpoints, data handling, and deployment configuration. Third-party GitHub vulnerabilities should be reported to GitHub through its own security process.
